# Local host: threat → enforcing code → executable evidence

[Run the pilot](README.md) · [Threat model](../../docs/THREAT-MODEL.md) · [Specification traceability](../../conformance/TRACEABILITY.md)

This profile evaluates the local Python/SQLite host and its sandbox provider. It does not mark generic product-wide requirements passed. Each backend test below is a method in [HostIntegrationTests](tests/test_host.py), invoked by `npm run test:host`. Named results and source hashes are in `artifacts/host-backend-results.json`; browser results are retained separately.

The [browser suite](browser/host.spec.ts) proves that a post already exists at the sandbox provider while the page still has no `.tun-receipt`, then verifies that the receipt appears only after a server readback. It also covers an actual dropped HTTP response, reconnection, absent readback, stale-browser revocation, separate withdrawal, and a narrow-screen keyboard/accessibility sample. [Client tests](../../tests/host-client.test.ts) reject premature or mismatched receipt payloads.

The existing conformance collector currently ingests Vitest mappings, not this new Python result format. This file links separate executed evidence; it does not silently increase the collector's coverage count. Production adoption must repeat the relevant scenarios against the selected identity system, transaction store, worker, and provider and complete the residual review for each applicable rule.
